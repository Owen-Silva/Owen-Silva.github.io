01 — How I work

Claude Code as a pair programmer

I build with Claude Code as a pair programmer. A few of the projects on this site are tools I made for working that way, and they are the ones I reach for most.

All three have their own entries on the projects page, with dates and state. Autopilot and Mission Control are paused; VOLT is in weekly use.

Atlas Autopilot

An unattended AI developer. A worker builds from a task list, a separate AI reviewer decides what merges, and a watchdog keeps an eye on the live site. The worker cannot push; only the reviewer can merge to the branch that deploys.

Mission Control

A live dashboard of Claude and its helper agents at work, drawn as a radial graph next to a 50-node system map of Atlas’s infrastructure. Zero npm dependencies; it streams updates over server-sent events.

VOLT

A terminal AI assistant that talks to a dozen model providers and keeps one history and spending ledger across all of them. Zero dependencies, 188 test checks against a mock server, and it imports Claude Code’s sessions without double-counting.

02 — The numbers

How everything here was counted

Measured on 12 October 2026 from git history, file counts and the live sites, counting commits through 11 October. Where a project has no git history, its dates come from its files.

The commit river on the front page is built from the per-day commit counts of three repositories — Atlas, the academy portal and Quartz, my browser — bucketed by UTC author date. Every dot in it is one commit; there are 3,176 of them, and nothing is sampled or rounded to make the picture work. Across all 31 of my repositories, counted the same way, there are 3,750.

Two different line-counting rules appear across the site and they do not reconcile, so they are never shown side by side. The 875,541-line census counts code lines. The per-project figures in the write-ups come from git ls-files | wc -l, which counts every line in a different file set. Both are stated with the rule that produced them.

Commits

git rev-list --count on each repository’s production branch: 2,720 for Atlas, 210 for the portal, 246 for Quartz.

Dates

git log --date=short | sort -u for the days work actually landed: 112 for Atlas, 37 for the portal and 13 for Quartz, in local time.

Shape

Data models from the schema, endpoints from the route files, screens from the view directory, releases from the product’s own changelog.

Not remeasured

A few of Atlas’s derived figures — test-file counts, eval runs, its app and test line counts — were not recounted on 16 September or 12 October. Atlas has shipped since, up to v1.3.1.1 on 4 October, so read them as approximate.

03 — What is left off

On purpose

Trading results

Several projects here are trading tools. No returns, balances or positions appear anywhere on this site.

Client and family data

The academy portal holds real families’ information. None of it — no names, rosters, accounts or screenshots of signed-in screens — is published here.

Security details

The Atlas system map publishes the shape of the system and nothing else: no hostnames, ports, endpoint paths, environment-variable names, buckets, deployment identifiers, file paths or live probe readings.

04 — This site

How it is drawn

Static files: seven HTML pages, one stylesheet, a handful of scripts and six JSON files. No build step, no framework, no graphics library. The only external requests are three typefaces from Google Fonts — Fraunces, Schibsted Grotesk and IBM Plex Mono.

The scenes are my own WebGL: one vertex per commit for the river, a domain-warped noise field for the ink-wash ground, painted once per resize rather than per frame. Every render loop stops the moment its scene settles, and stops early if it scrolls out of view.

The ground is CSS, never WebGL, so if a graphics context fails or is lost the page keeps its ink and every word stays legible — and says so, with the reason, rather than failing quietly.

Data

Every number on the site is read at runtime from the JSON files in /data and checked against what the page has printed. A disagreement is shown, not hidden.

Motion

Each scene plays once and settles. prefers-reduced-motion gets the settled frame with the same information and no animation at all.

Reach

Every page is checked at 1280, 393 and 320 pixels wide, in both the ink and the paper theme, with the keyboard and with contrast measured against what is actually rendered.
